# セキュリティ上の注意

## 最初に：提出版はデモモード（認証なし）です

この提出版は初期状態で `DEMO_MODE=true` となっており、**ログインを求めず、
APIの権限チェックも通しません**。下記「実装済み」の対策はコードとして揃っていますが、
デモモードの間は認証・権限の部分が意図的に無効化されています。

- デモ環境に**実在の個人情報や機密情報を保存しないでください**
- 実データを扱う時は `DEMO_MODE` と `VITE_DEMO_MODE` を両方 `false` にしてください
- 切り替え手順は [MAINTENANCE_GUIDE.md](MAINTENANCE_GUIDE.md) の1章

なお、アカウント管理の画面は同梱していません（APIと権限の仕組みはサーバー側に実装済みです）。

## 実装済み（ログイン有効時に機能します）

- パスワードをArgon2でハッシュ化
- JWTへ有効期限を設定
- パスワード変更時に旧JWTを無効化
- 停止アカウントのJWTを拒否
- API側で管理者権限を検査
- 自分自身の管理者権限削除・停止を拒否
- 有効な管理者が0人になる変更を拒否
- CORSを登録済みURLへ限定
- DB接続文字列と秘密鍵を環境変数化
- APIエラーでDB接続文字列などの内部情報を返さない

パスワードハッシュとJWTの実装方針は、FastAPI公式のセキュリティチュートリアルを主な一次情報として採用しています。

- [FastAPI公式：OAuth2 with Password and JWT](https://fastapi.tiangolo.com/tutorial/security/oauth2-jwt/)
- [RFC 9106：Argon2](https://www.rfc-editor.org/info/rfc9106/)

## 本番導入前に追加検討が必要

| 項目 | 現状 | 本番向け対応 |
| --- | --- | --- |
| 通信暗号化 | Netlify・RenderのHTTPSに依存 | クライアント環境でもHTTPS必須 |
| JWT保存 | ブラウザのsessionStorage | 企業要件によりHttpOnly CookieやSSOを検討 |
| ログイン試行制限 | 未実装 | レート制限・一時ロックを追加 |
| 監査ログ | 未実装 | 誰が投稿・編集・権限変更したか記録 |
| パスワード複雑性 | 12文字以上 | クライアント規程へ合わせる |
| MFA | 未実装 | IdP・SSO側で対応を検討 |
| バックアップ | DBサービス側設定 | 保存期間・復旧テストを契約で決定 |
| DBスキーマ更新 | `create_all`で初期作成 | 長期運用前にAlembic等の移行管理を導入 |

## 重要な制約

この提出版はポートフォリオ／小規模検証向けの安全性を高めた構成です。個人情報やクライアントの機密情報を保存する本番システムとして、そのまま無条件に適合すると断定はできません。

本番要件は、クライアントの情報セキュリティ規程、個人情報の種類、保存期間、アクセス監査、ネットワーク構成によって変わります。一次情報としてクライアントのセキュリティ規程、委託契約、システム要件定義書の確認が必要です。
